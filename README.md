# Agent 速度模拟器

给准备买 Mac Studio 本地部署 **GLM-5.3-Flash** / **Qwen3.8-Flash-Next** 的人：一个 Agent 回合的时间到底花在哪？在线体验：**https://linwei-chen.github.io/agent-speed-simulator/**

把一次 Agent 回合拆成三段，按真实时间推进：

1. **预填充（prefill）**——你发消息时，模型要把系统提示、全部历史对话、文件、工具返回一次性读完。上下文 195K 时，哪怕预填充速度 1,835 tok/s，也要干等 106 秒才吐出第一个字。
2. **思考（thinking）**——推理模型正式回答前先打草稿，这部分 token 你看不见，但按同样的速度实打实计时。
3. **逐字输出（decode）**——你看到的打字机效果，受显存带宽限制，就是大家说的 tok/s。

## 在线使用

选运行环境（本地 8 个上下文档位 / 云端）、任务量级（轻 600 字 / 中 2000 字 / 重全文）、倍速（建议 5×，195K 大上下文用 20×），点「运行模拟」。每回合会在下方时间轴记一条三段色对比条，多跑几档即可横向对比。

## 数据来源（不编造）

本地速度取自 oMLX 在 **M5 Ultra（64 核 / 256GB）** 公开基准的 2026-10-12 快照，逐档录入：

| 上下文 | 预填充 tok/s | 解码 tok/s | 上下文 | 预填充 tok/s | 解码 tok/s |
|---|---|---|---|---|---|
| 1K | 459.2 | 37.3 | 32K | 1,953 | 87.4 |
| 4K | 1,221 | 41.6 | 64K | 1,925 | 60.5 |
| 8K | 1,960 | 72.4 | 128K | 1,887 | 96.1 |
| 16K | 1,971 | 99.1 | 195K | 1,835 | 42.6 |

Qwen3.8-Flash-Next-oQ4e-mtp：16K 4,673/115.7 · 32K 4,772/110.2 · 64K 4,698/139.9 · 128K 4,560/129.0。

注意：**解码速度随上下文非单调波动**（1K 最慢、16K 峰值、195K 回落）是快照里的真实形态，不是数据错误——两端各有解释：1K 档被固定开销摊薄，195K 档是 KV 缓存变大后每 token 都要扫更长的记忆，中间锯齿来自调度与带宽波动。

云端场景为口径假设（非实测）：Flash 解码 60 tok/s、FlashX 约 200 tok/s（官方标称），128K 上下文按 KV 缓存命中建模，首字等待 0.8~1.0 秒。真实 Agent 端到端参考：某 ZCode 使用库中位 7,401 token / 66.5 秒 ≈ 111 tok/s（GLM-5.3-Flash 会话压缩任务，含思考）。

## 换算口径

- 中文：1 token ≈ 1.67 个汉字（大词表模型，参照 DeepSeek/Qwen 公开口径 0.6 token/汉字）
- 英文：1 token ≈ 0.75 个单词
- 人类默读：约 10 字/秒——所以 60 tok/s（≈100 字/秒）的输出，瓶颈永远是你的眼睛，而不是模型

## 本地运行

无需构建、无外部依赖：克隆仓库后直接用浏览器打开 `index.html` 即可。
